# 宿主能力与迁移边界

本包不绑定模型、平台、代理 API 或进程形式。核心是研究协议、当前方法与可读写的个体目录；安装只建立文件与入口。

| 能力 | 可核对事实 | 不可推定的事实 |
|---|---|---|
| 文件连续性（L0） | 能读协议、写状态与交付文件 | 能执行脚本、自动加载 skill |
| 本地执行（L1，可选） | 命令实际运行并保存退出码与日志 | 程序输出证明了研究结论 |
| 独立伙伴（L2，可独立于 L1） | 第二上下文启动，有学生可维护的目录、记忆与交接产物 | “子代理”或“新聊天”这个名称本身保证上下文、记忆或权限隔离 |
| 专业工具（L3，可选） | 实际用过检索、排版、计算或领域工具并留下出处与产物 | 仅因工具已安装就声称结果由它验证 |

区分材料**已携带**、入口**已接入**、工具或学生**已运行**、方法**已见效**：每一步只按相应证据陈述。方法所依赖的宿主能力暂缺时，保留其可读说明并报告缺口；真实重复劳动出现后，宿主可按需写小工具，不设经验必须变成代码的门槛。

另外记录**访问边界**：学生目录与导师目录是否分开、双方实际读写了哪些文件、宿主是否曾用权限拒绝目录外访问。不同目录只是组织方式；硬性读写隔离必须有宿主权限证据。缺执行能力仍可有独立伙伴（例如两个只会读写文件的独立会话）；缺第二上下文时如实称协助或自查。

## 首次派发时再读

1. 这条独立路线能否找到反例、改变决策或节省主线时间？短问题由主智能体直接解决。
2. 在当前平台列出实际可用方式（独立任务、子代理、外部命令行、图形工作区、人工接力），用同一组条件比较：新上下文、学生自己的持久目录与记忆、可恢复的回执、工具能力、权限与成本。不设跨平台默认宿主。
3. 选定学生根与任务包后按 `modules/handoff.md` 建立入口与首轮任务。

宿主不会自动发现 `SKILL.md` 时，把它当普通可读文件在首次任务中明确指定。命令不可用时走文件路径，不把未运行的检查写成已完成。某个平台在一次试点中更便宜只是该次经验，不写进通用协议。
