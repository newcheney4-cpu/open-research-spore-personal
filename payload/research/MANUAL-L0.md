# 只有文件读写能力时的落地方法

1. 先看非空目标中将要复制的同路径内容。只想借用方法时直接阅读相关文件即可，不必伪装成已安装；导师个体已在本工作区时也无需重装。决定手工安装后，导师配置把发行包 `payload/research/` 的相对结构复制到 `research/`；学生配置把 `payload/student/` 复制到学生工作区根目录。
2. 已有同名且内容不同的文件先保留并报告冲突，不手工覆盖；已有范式的接管由项目宿主逐处判断。
3. 让接收方读 `WAKEUP.md`（学生读 `START.md`）和当前任务；宿主不会自动读取时，把入口文件粘进本轮对话。
4. 在 `STATE.md` 写目标和下一个动作；真正影响结论的陈述记入台账，证据尚未运行就写“未运行”。

L0 无法运行 `tools/check.py`、`tools/spore.py` 或安装器。`MANIFEST.json`（发行包）或 `PACK-MANIFEST.json`（已安装个体）可用于逐文件手工核对 SHA-256，但仅凭复制完成不能声称验证通过。

之后获得 Python 执行能力时，在原目标运行 `python <包根>/install.py --root <目标> --write`：相同文件跳过、已修改文件保留、缺失运行文件可用 `--restore-missing` 单独修复。然后运行 `python <个体>/tools/check.py --source-root <个体>`；不要把旧环境的示例输出当作新机器记录。

第一次真正派发给学生且能写文件时，按 `modules/handoff.md` 确定与导师分离的学生目录，用 `tools/first_student.py`（或手工复制 `student-seed/` 加运行资源）建立学生个体，并把本轮任务放进其 `public/`。没有新上下文或无法确认隔离时，把结果标为自查或协作；准备目录与回执都不是运行证据。

生成后代需要脚本能力；没有 Python 时按同样规则手工复制并重新计算清单，只选择 `INHERITANCE.json` 中的内容，不带个人记录与当前任务状态。无法证明来源时如实记录“接管/手工迁移”，不要用重复安装覆盖本地文件。
